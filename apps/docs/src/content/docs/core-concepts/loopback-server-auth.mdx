---
title: Loopback Server & Auth
description: One HTTP+WS server serves the app, media, and protocol socket.
---

One loopback HTTP+WS server (`core/server/static-file-server.ts`, with its
admission policy in `core/server/loopback-gate.ts`) serves the
web app at `/`, the media files mounted by plugins, and the framed-protocol
WebSocket socket. On device it binds `127.0.0.1` on an ephemeral port, and
every gated request is authorized by a per-session credential:

1. The host starts the worklet, which writes `{ origin, port, bootstrap }` to
   `handoff.json` (never the session token). The host injects **only the one-time `bootstrap` nonce**
   into the page (`window.__ekrooh = { bootstrap }`), never the raw token.
2. The page exchanges the bootstrap nonce for a `bare_session_<port>` cookie
   via `POST /login` (`HttpOnly; SameSite=Strict; Path=/`). Cookies are scoped
   to the host, not the port, so the port in the name keeps two loopback
   servers sharing one cookie store from overwriting each other's session. The nonce is
   single-use: after the page redeems it, it is spent. The raw session token
   is never accepted as a login body.
3. The cookie then authorizes `<img>`/`<video>`/`fetch` and the WebSocket
   upgrade. Non-browser clients use the `X-Bare-Token` header. There is **no**
   `?token=` query-param path — a token must never appear in a URL.
4. The host loads `http://127.0.0.1:<port>/index.html` and deletes
   `handoff.json`. A host that needs the session token for its own
   `X-Bare-Token` calls gets it from `runtime.start()` inside the worklet, not
   from disk.

Every request, in every mode, must also pass the **origin rule**: its `Host`
must name the bound server (`127.0.0.1`, `localhost` or `[::1]` on the bound
port), which defeats DNS rebinding, and an `Origin`, when sent, must be that
server or one listed in `allowedOrigins`. WebSocket upgrades are not subject to
CORS, so this is what stops another site open in the same browser from driving
the backend. With auth on, an upgrade without an `Origin` is refused.

The dev backend (`mode=dev`) runs the same bundle with auth off on a fixed port
(`ws://localhost:8080`), so browser dev needs no credential, but the origin
rule still applies: the Vite dev server's origin is passed as
`origin=http://localhost:5173`.

HTML documents carry a Content-Security-Policy whose `connect-src` names the
one protocol socket the page may open (`ws://<host>:<port>`), not any `ws:`
host. A directory mount never serves a file whose real path (symlinks
resolved) lies outside the mount root, and a path segment that decodes to
`.`, `..`, a separator or NUL is a 400.

## Public vs gated (the threat model)

On one loopback origin, only the **bootstrap page** is public, and only because
a fresh WebView must load it before it can `POST /login`:

- **Public (pre-auth):** the explicit bootstrap directory mount at `/` — the
  bundled web app — marked `mountDir('/', dir, { public: true })`.
- **Gated:** every file mount (media), the WS upgrade, custom routes, and any
  directory mount **not** marked `{ public: true }`. A non-public directory
  mount 401s unauthenticated and 404s unknown paths (no SPA fallback to the
  bootstrap `index.html`).

Publicness is an explicit opt-in marker, never a property of the mount kind.

```ts
import { createLoopbackServer } from '@ekrooh/bare/runtime';

const server = await createLoopbackServer();
server.mount('/media/photo-1', '/path/to/photo.jpg'); // gated
server.mountDir('/photos', '/path/to/photos', { public: false }); // gated
const url = await server.url('/media/photo-1');
```

## Security notes

- Tokens are never placed in URLs or exposed to page JS — only the one-time
  bootstrap nonce, and the session cookie is `HttpOnly`.
- `Referrer-Policy: no-referrer` on all responses.
- WS upgrade origin check, single-client policy, idle timeout.
- Media mounts are per-session URLs — the mount id is unguessable.

The full decision, including the tradeoff vs per-resource capability tokens
(deferred), is an ADR: `docs/adr/0003-loopback-auth-surface.md`.
